Primitive ML dataset — configuration & how to run

This project generates parametric multi-story ETABS frame models from a JSON config. Geometry and constraints are resolved in metres (MKS) internally; you may author configs in MKS/SI metre keys or use FPS-style aliases (feet / inches) that are converted at load time. The response pipeline supports CSI present units (csi_present_units.py) and database table output options (csi_table_output_options.py) so CSV exports match ETABS GUI behaviour.

1. Config files (MKS vs FPS)

Two starter configs ship in the project root:

FileTypical useGeometry keysetabs.units
primitive_ml_dataset.default.json Metre-based editing (MKS) Sx_m, Sy_m, h_story_m, hb_m, … Often "mks" (kN, m, °C)
primitive_ml_dataset.default.us_fps.json US-friendly numbers in config Sx_ft, Sy_ft, h_story_ft, hb_in, ts_in, … (converted to metres when loaded) "us" (kip, ft, °F)

Conversion is handled by primitive_sampling.normalize_length_unit_aliases() (e.g. 1 ft = 0.3048 m, 1 in = 0.0254 m). After load, sampling and constraints use the same internal metre-based keys regardless of which file you started from.

1.5 constraints (Engineering Rules)

Accept/reject bands on derived geometry after a primitive sample is resolved. If a randomly generated building violates any of these rules, it is thrown away and a new one is drawn. This prevents ETABS from analyzing physically impossible or highly unrealistic structures.

Many entries are a two-number list [low, high]; some are a single scalar factor. Units on length-based constraints follow the key: Smax_m / h_story_m in MKS, or Smax_ft / h_story_ft in FPS configs (converted to metres internally).

1.5.1 Geometric & System Proportions

  • plan_aspect_ratio: [min, max] ratio of Ly / Lx (building footprint).
  • elevation_aspect_ratio: [min, max] ratio of total height to minimum plan dimension.
  • internal_bay_variance: [min, max] ratio of min(Sx, Sy) / max(Sx, Sy). Prevents extremely long, narrow bays.

1.5.2 Beam & Slab Rules

  • hb_over_Smax: [min, max] span-to-depth ratio for beams. Ensures beams are deep enough for the span but not absurdly huge.
  • ts_over_Smax: [min, max] span-to-depth ratio for slabs.
  • beam_aspect_ratio: [min, max] ratio of beam width to depth (bw / hb).
  • beam_flat_max_ratio: Maximum allowed bw / hb. If set to 1.0, flat beams (wider than they are deep) are rejected.
  • beam_onto_column_max_ratio: Maximum allowed ratio of beam width to column width. If 1.0, beams cannot be wider than the columns they rest on.
  • beam_slab_bw_over_ts_min: Ensures the beam width is at least this many times the slab thickness.

1.5.3 Column Rules

  • column_aspect_ratio: [min, max] ratio of min(bcx, bcy) / max(...). Prevents blade-like wall-columns.
  • column_side_ratio_max: Absolute cap on column rectangularity (e.g., 3.0 means one side can't be more than 3x the other).
  • column_slenderness_max: Maximum ratio of story height to minimum column side. Prevents toothpick columns.
  • column_vs_beam_factor: Forces a minimum column dimension relative to the beam depth (e.g., 0.62 * hb).
  • column_area_index & ext_to_int_col_area_ratio: Controls how much smaller top columns and exterior columns can be compared to the base interior columns.
  • scwb_stiffness_ratio_min: Strong-Column/Weak-Beam check. Approximates the stiffness ratio to ensure columns are stiffer than the beams framing into them.

1.6 analysis_inputs

Used by the post-build / response pipeline (not the bare geometry sampler):

  • super_dead_value, live_value — uniform slab area loads. Values must match ETABS force/area units for the active present-unit system (after SetPresentUnits if set). MKS metric tables often use kN/m²; the US FPS preset typically uses ksf (e.g. 0.02, 0.05).
  • seismic_design_code — "asce7_16" (default) or "ubc97". Chooses which auto-seismic API path runs for QX / QY. CLI override: --seismic-design-code ubc97.
  • ASCE 7–16 (when code is asce7_16): seismic_x_name, seismic_y_name, seismic_ss, seismic_s1, seismic_r, seismic_site_class.
  • 1997 UBC (when code is ubc97): optional nested object ubc97 for SapModel.LoadPatterns.AutoSeismic.SetUBC97 — direction (DirFlag), eccentricity, period_flag (0 = program period), ct, period_t (T), z, soil_profile, importance_i, r, near_source_na / near_source_nv, top_story / bottom_story (names; blank = auto from the model). Legacy seismic_zone maps to z if omitted.
  • present_units — optional string passed to SapModel.SetPresentUnits at the start of structured_analysis_export (see csi_present_units.py). Use null to leave the model’s units unchanged. Must be one of the allowed ids for csi_product (ETABS has six; SAP2000 allows more).
  • csi_product — "etabs" or "sap2000"; gates which present_units strings are valid.
  • apply_csi_table_output_options — if true (default), merges csi_table_output_options with defaults and applies Results.Setup plus DatabaseTables.SetTableOutputOptionsForDisplay / SetOutputOptionsForDisplay before CSV export (see csi_table_output_options.py).
  • csi_table_output_options — optional object overriding envelope vs step-by-step behaviour for database tables (details below).
  • asce716_load_combinations — optional object: preset packs (CONC_* / STL_* / SLAB_*) via apply or template_combos, plus optional custom_combos to define your own linear-add combinations in JSON (see §1.6.3).

1.6.1 CSI present units (present_units)

Separate from etabs.units (new-model init). analysis_inputs.present_units only affects the export run: it sets ETABS’s current unit system so slab inputs and table/CSV numbers are consistent.

csi_productAllowed present_units strings (examples)
"etabs" lb_in_F, lb_ft_F, kip_in_F, kip_ft_F, kN_mm_C, kN_m_C — six systems total (csi_present_units.ETABS_PRESENT_UNITS).
"sap2000" Includes the six above plus metric variants such as N_mm_C, kgf_m_C, … (SAP2000_PRESENT_UNITS).

Practical pairing: etabs.units "mks" → often "kN_m_C"; "us" → "kip_ft_F". For "si" (builder uses N, mm internally) the ETABS string whitelist has no N_mm_C; many teams keep present_units as null or align loads carefully. Invalid strings fall back via resolve_present_units — prefer exact ids from the source file.

1.6.3 asce716_load_combinations (response combos)

Preset packs — When "template_combos" is omitted, it follows legacy "apply": true. structured_analysis_export.run_pipeline calls apply_response_combinations using pattern names from the pipeline (etabs.dead_pattern, live_pattern, super_dead_pattern, seismic names), unless overridden in JSON.

Custom / overwrite in JSON — Use "custom_combos" as an object mapping combo name → list of [load_pattern_name, factor] pairs (linear add). Example:

"custom_combos": {
  "USER_ULS": [["DEAD", 1.4], ["LIVE", 1.6]],
  "USER_SLS": [["DEAD", 1.0], ["LIVE", 1.0]]
}

Alternative form: "custom_combos": [{"name": "USER_ULS", "terms": [["DEAD", 1.4]]}]. Terms may also use objects {"pattern": "DEAD", "factor": 1.4}.

Set "replace_existing_combos": true to RespCombo.Delete each custom name before re-adding (lets you redefine a name). Set "template_combos": false with "apply": true to skip preset CONC_* packs but still allow custom_combos; or use "apply": false with only custom_combos for user-defined combos alone.

JSON keyRole
applyLegacy: when true and template_combos omitted, preset packs run.

design_setsWhich preset packs: "concrete_frame", "steel_frame", "slab_gravity" (default all three).

Preset factors remain in _combo_templates; custom_combos is the supported way to set arbitrary factors in JSON.

CLI equivalent: structured_analysis_export.py --asce716-load-combos-json path\\or\\inline.json.

2. Prerequisites

  • Windows, ETABS installed and licensed.
  • Python 3 with dependencies used by the repo (e.g. numpy, comtypes, pandas for CSV export).
  • Run commands from the project directory that contains the JSON configs and run_primitive_ml_dataset.py.

2.1 Setting up Python (Virtual Environment)

Before running the scripts, it is highly recommended to create a virtual environment and install the required packages so you don't get ModuleNotFoundError or missing package errors.

# 1. Open your terminal in the project folder and create a virtual environment
python -m venv venv

# 2. Activate the virtual environment
# On Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# On Windows (Command Prompt):
.\venv\Scripts\activate.bat

# 3. Install the required packages
pip install comtypes numpy pandas

3. How to run

3.1 Batch generator (recommended)

# MKS config — build up to 20 models under ./out_mks (0 = use config target_accepted)
python run_primitive_ml_dataset.py --config primitive_ml_dataset.default.json --out ./out_mks --limit 20

# US / FPS config
python run_primitive_ml_dataset.py --config primitive_ml_dataset.default.us_fps.json --out ./out_us --limit 20

# Geometry validation only (no ETABS COM)
python run_primitive_ml_dataset.py --config primitive_ml_dataset.default.json --out ./dry --no-etabs --limit 100

# Force full analysis export on/off regardless of JSON
python run_primitive_ml_dataset.py --config primitive_ml_dataset.default.json --out ./out --limit 5 --with-analysis-responses
python run_primitive_ml_dataset.py --config primitive_ml_dataset.default.json --out ./out --limit 5 --no-analysis-responses

# Override lateral seismic code (default comes from JSON analysis_inputs.seismic_design_code)
python run_primitive_ml_dataset.py --config primitive_ml_dataset.default.json --out ./out --limit 3 --seismic-design-code ubc97

# Override ETABS unit preset from CLI
python run_primitive_ml_dataset.py --config primitive_ml_dataset.default.json --out ./out --limit 1 --units mks

Use python run_primitive_ml_dataset.py --help for slab load pattern overrides, --export-all-available-tables, and other response-pipeline flags. Use --seismic-design-code to force ASCE 7–16 vs UBC 97.

3.2 Single-model export (structured_analysis_export.py)

For one .edb without the batch sampler, run the same post-build + CSV pipeline directly. Useful for fixtures under models/ or any saved model.

python structured_analysis_export.py --help
# Open a file (starts ETABS if needed) and write under .\exports\<stem>_<timestamp>\ …
python structured_analysis_export.py --edb models\asce716_full_workflow_test.EDB --out .\exports --present-units kN_m_C
# Attach to an already-open model instead of --edb:
python structured_analysis_export.py --attach --out .\exports --no-csi-table-output-options

Flags include --present-units, --csi-product, --table-output-json (JSON string of overrides), and --no-csi-table-output-options to skip Results.Setup / database table setters.

3.3 Single entry via main.py

Edit USER_SETTINGS inside main.py (output folder, limits, nested config dict), then:

python main.py

3.4 Where batch outputs go

Under your --out folder (or main.py output_folder):

  • config_resolved.json — copy of the merged config used for the run.
  • batch_manifest.json — run-level summary (UTC stamp, accepted count, draws, seismic/load settings, model_ids).
  • runs.jsonl — one JSON record per accepted model (paths, mesh counts, story sync, present-unit codes, etc.).
  • summary.csv — flat table for spreadsheets.
  • models/<model_id>/model.edb — ETABS model.
  • If analysis responses are on: models/<model_id>/responses/<timestamp>/manifest.json and Analysis Results/…/*.csv (including 0_All_Available_Tables when full table export is enabled).
